# v0.43.0.0 — Upstream sync (gbrain v0.37.9.0 → v0.42.8.0)

## What changed

- **73 upstream commits merged** in one wave. New capabilities: `gbrain connect`
  (wire a coding agent to the brain from a bearer token in one command),
  `gbrain onboard`, `gbrain enrich --thin` (brain-internal grounded synthesis
  for stub pages), search autocut (result sets sized by score discontinuity),
  a content-quality gate on sync (junk quarantined, boilerplate flagged),
  `gbrain skillopt` (self-evolving skills, default OFF), `gbrain extract --stale`
  + a doctor lag check, `gbrain status`, `doctor --scope=brain`, `--workers N`
  on bulk commands, a 94→15 canonical type unification, and a minions/queue
  reliability wave.
- **New schema migrations** apply automatically the next time you run `dbrain`
  (the `postinstall` hook calls `dbrain apply-migrations --yes`, and every
  command path applies pending migrations on connect).
- **Version leapfrogged to v0.43.0.0** to end the number collision between the
  fork's version line and upstream's v0.42.x track.
- **The fork's sync-resilience gate is preserved.** The v0.40 behavior (a
  deterministic bad file is quarantined and the sync advances, rather than
  freezing the whole brain) is intact, now merged with upstream's
  `--no-schema-pack` / `--no-extract` / single-source `--timeout` flags.

## Will my brain work worse if I do nothing?

**No.** Schema migrations apply on their own. Your `access_tokens`, recipe
files, and existing embeddings are untouched. The new onboarding commands are
additive — the teammate plugin flow you already use is unchanged.

## Heads-up: the default embedding model changed upstream

The canonical default embedding model is now `zeroentropyai:zembed-1` (1280-dim)
instead of `openai:text-embedding-3-large` (1536-dim). This only affects a
**fresh** `dbrain init`:

- **Existing brains** read the embedding model from your `~/.gbrain` config and
  stay on whatever they were initialized with. Nothing re-embeds on upgrade.
- **A new `dbrain init`** now defaults to zembed-1 and wants `ZEROENTROPY_API_KEY`.
  To stay on OpenAI for a fresh brain:

  ```bash
  dbrain config set embedding_model openai:text-embedding-3-small
  ```

## Optional: the new onboarding surface

`gbrain connect` wires a coding agent to the brain from a bearer token in one
command; `gbrain onboard` is the guided activation flow. Both land alongside the
fork's teammate plugin install + `access_tokens` path. Either works — pick the
one that fits. See `docs/tutorials/connect-coding-agent.md`.
