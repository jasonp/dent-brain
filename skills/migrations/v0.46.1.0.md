# v0.46.1.0 — Granola-sync identity dedup + `includeFolders` is required

## What changed

- **New brain op `get_page_by_identity(key, value)`.** Returns the page whose
  `frontmatter->>key = value`, source-scoped, or `{ exists: false }`. Additive
  and read-scope — no action needed for it on its own. It's what lets ingestors
  dedup on a stable external id they stamped into frontmatter instead of a slug.
- **Granola-sync keys dedup on `granola_document_id`, not the meeting slug.** A
  Granola title rename used to fork a second page (new title → new slug → the
  old slug-based existence check missed). Now the daemon looks the note up by
  its document id and reuses the existing page's slug, so a rename updates in
  place. Enrichment is idempotent and the `## Mentioned` section is written last
  as a completion marker, so a run killed mid-enrichment finishes next time
  instead of leaving a half-filed page forever.
- **The user filter must export `includeFolders: string[]`.** The reconcile loop
  pulls those Granola folders' recent notes server-side each run. A filter
  without it makes the daemon fatal-exit on startup.

## Will my brain work worse if I do nothing?

**Only if you run the granola-sync daemon.** Everyone else: nothing to do — the
new op is additive and the dedup change is internal to the daemon.

If you DO run granola-sync: after you pull this release, the daemon code
updates. If your `tools/granola-sync/user/filter.ts` predates the folder-scoped
reconcile and does **not** export `includeFolders`, the next scheduled run
exits with:

```
[granola-sync] FATAL: <path>/user/filter.ts must export `includeFolders: string[]` …
```

and stops syncing until you fix it.

## Operator steps (granola-sync users only)

### 1. Add `includeFolders` to your filter

Either regenerate the filter (recommended — it also picks up the current recipe
contract):

```
/dent-extensions setup granola-sync
```

…or hand-edit `tools/granola-sync/user/filter.ts` to add the export, naming the
Granola folder(s) the daemon should pull each run:

```ts
export const includeFolders = ['Dent'];
```

(See `tools/granola-sync/recipe/filter.example.ts` for the full template.)

### 2. Confirm it runs

```bash
bun tools/granola-sync/sync.ts --dry-run
```

Expect the run to authenticate, list your include folders, and report candidate
counts. No `FATAL` line = you're good. A normal run reconciles the window and
short-circuits anything already filed.

## Notes

- **No backfill needed for existing meetings.** Identity dedup reads the
  `granola_document_id` your earlier syncs already wrote into each meeting's
  frontmatter — every page is already keyed, retroactively.
- **One-time re-enrichment is harmless.** The first run after upgrade may
  re-touch a meeting whose `## Mentioned` marker is absent (older pages predate
  the always-write marker); attendee bullets and the Mentioned block are both
  idempotent, so nothing duplicates.
- **Late filing still self-heals — by note creation time.** A meeting filed into
  an include folder is picked up next run as long as its note was *created*
  within the look-back window (`GRANOLA_SYNC_LOOKBACK_HOURS`, default 48). An
  older note needs a one-off `--since YYYY-MM-DD` backfill.
