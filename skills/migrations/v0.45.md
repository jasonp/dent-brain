# v0.45.0.0 — Single Postgres brain (DB canonical, git demoted to mirror)

## What changed

- **Writes are DB-direct.** `markdown_append_to_page` / `markdown_replace_page`
  and the regfox/mailchimp ingestors land in Postgres on source `dent` via
  `importFromContent` — no git pull/commit/push on the write path anymore.
- **Page history moved from git to the DB.** Inspect prior snapshots with
  `get_versions`; the old "look at the git log" workflow is gone.
- **The data repo is now a derived mirror.** A nightly exporter
  (`DENT_BRAIN_EXPORT_HOUR_UTC`, default 10:00 UTC) renders every live `dent`
  page to `<slug>.md` and pushes one commit. `export_brain_now` triggers the
  same path on demand. The exporter owns every nested `*.md` file; repo-root
  files and any path with a `.`- or `_`-prefixed segment are human-owned and
  never touched.
- **The server no longer ingests from git.** The scheduled pull is deleted and
  the `dent` source row is marked `{mirror: true, syncEnabled: false}`.

## THE WORKFLOW CHANGE — read this twice

**Hand-edits pushed to the data repo are NO LONGER ingested.** The mirror is
one-way: DB → git. If you edit a `<slug>.md` file in the data repo by hand,
the next nightly export will **overwrite it** with the DB rendering (or delete
it, if no live DB page matches the path). To change brain content, write
through the MCP ops (`markdown_append_to_page`, `markdown_replace_page`,
`put_page`) or the CLI. Repo-root files and `.`/`_`-prefixed paths (README,
workflow notes, `_meta/…`) remain yours to edit.

## Will my brain work worse if I do nothing?

**Yes, until the reconciliation runs.** Pre-v0.45 brains have up to three
divergent copies of a page (source `dent`, source `default`, and the git
file). Reads are `dent`-scoped, so content stranded on `default` or only in
git stays invisible until step 3 below converges everything onto `dent`.

## Operator steps (in order)

### 1. Deploy v0.45

Merge + `railway up --detach` (the GitHub → Railway hook is broken; deploys
are manual). From this moment writes flip to DB-direct and the git repo is
frozen as input — nothing reads from it except the migration script below.

### 2. Pin the pre-deploy data-repo commit

Record the data repo's commit from **before** the deploy:

```bash
git -C /path/to/your-data-repo rev-parse origin/main   # BEFORE any export fires
```

Save that sha. Do **not** re-resolve it later — once the nightly exporter
fires, HEAD is rewritten from DB state and is useless as a reconciliation
input. The script only reads the repo via `git show <ref>:<path>`, never HEAD.

### 3. Run the reconciliation script

```bash
# Dry-run: full per-slug decision report, zero writes.
DATABASE_URL=... bun run scripts/dent/migrate-v0.45-single-brain.ts \
  --repo /path/to/your-data-repo --repo-ref <pinned-sha> \
  --report /tmp/v045-report.jsonl
```

Review the report (one JSON line per slug: decision, winner, timestamps,
hashes). Winner rule: all copies identical → keep `dent`; otherwise newest
wins (git commit time vs `pages.updated_at`); exact tie → git wins.

```bash
# Apply: same pass + importFromContent writes (source 'dent', noEmbed)
# + deletes the legacy `sync.repo_path` config key.
DATABASE_URL=... bun run scripts/dent/migrate-v0.45-single-brain.ts \
  --repo /path/to/your-data-repo --repo-ref <pinned-sha> --apply \
  --report /tmp/v045-apply.jsonl
```

**Verify:** spot-check a handful of slugs via `get_page` — include recently
written pages (e.g. the `daily/2026-06-11`-era archive pages that motivated
the split-brain fix), one page that existed only on `default`, and one that
only lived in git. Re-running `--apply` should report `writes: 0`
(idempotency check).

Then purge the now-redundant `default`-source rows (separate, irreversible):

```bash
DATABASE_URL=... bun run scripts/dent/migrate-v0.45-single-brain.ts \
  --purge-default          # preview counts per table
DATABASE_URL=... bun run scripts/dent/migrate-v0.45-single-brain.ts \
  --purge-default --yes    # delete (pages CASCADE takes the children)
```

### 4. Re-embed

Migration writes are `noEmbed`. Refresh embeddings:

```bash
railway run ... embed --stale   # or the equivalent for your deployment
```

### 5. First export

Trigger `export_brain_now` (admin op) and inspect the resulting commit on the
data repo. Expect: every live `dent` page materialized at `<slug>.md`, stale
managed files pruned, root-level/`.`/`_` files untouched, one commit
(`brain-export: N changed, M deleted`).

### 6. Railway env cleanup

- **Delete** `DENT_BRAIN_PULL_INTERVAL_SECONDS` — there is no scheduled pull
  anymore; the variable is dead.
- **Keep** the deploy-key variables (`DENT_BRAIN_DATA_DEPLOY_KEY`,
  `DENT_BRAIN_DATA_REPO_URL`, `DENT_BRAIN_DATA_PATH`,
  `DENT_BRAIN_DATA_BRANCH`) — the exporter still needs push access to the
  mirror. No deploy key → no mirror → exports disabled, everything else runs.
- Optional: `DENT_BRAIN_EXPORT_HOUR_UTC` to move the nightly export window.
