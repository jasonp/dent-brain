# v0.37.0 migration — granola-sync now uses the Granola public API

`gbrain upgrade` upgrades the dent-brain CLI itself, but **does not** update
per-teammate ingestor installs on individual laptops. If you have the
granola-sync launchd extension installed, you must re-run its installer once
to pick up the new code and mint a Granola API key. Without this, the daemon
will keep running v0.1 code that reads the now-encrypted Granola cache and
quietly never discovers new meetings.

## What changed

Granola encrypted `~/Library/Application Support/Granola/cache-v6.json` in their
latest desktop release. The hourly granola-sync daemon used to read that file
directly. As of v0.37, it talks to Granola's public REST API at
`https://public-api.granola.ai/v1/` with a per-teammate API key stored in the
macOS keychain (service `dent-brain.granola-sync`, account `$USER`).

Knock-on changes:

- No more 45-minute settle delay. The API only returns notes that already
  have a summary + transcript, so unprocessed meetings 404 and silently retry
  next run.
- Folder filtering reads each note's `folder_membership[]` directly (no
  pre-built map).
- Meeting pages drop the `## Chapters` section (not in the public API).
- `## Notes` now contains Granola's AI summary in markdown form
  (`summary_markdown`) — the user's hand-typed notes aren't exposed by the API.
- Transcript pages use absolute ISO timestamps from the API instead of relative
  offsets, and speaker source `"speaker"` renders as `(remote)`.

## What every teammate with granola-sync installed must do

```bash
# 1. In the Granola desktop app:
#    Settings → Connectors → API keys → Create new key
#    (requires Business/Enterprise plan; on Enterprise, your workspace admin
#    must have enabled "Allow personal API keys")
# Copy the grn_... key to your clipboard.

# 2. From your dent-brain checkout:
bash tools/granola-sync/install.sh
```

The installer will:

1. Detect that the keychain entry is missing.
2. Prompt you to paste the API key (input hidden).
3. Validate it against `https://public-api.granola.ai/v1/notes?page_size=1`.
4. Store it via `security add-generic-password -U -s dent-brain.granola-sync -a "$USER"`.
5. Copy the 6 new runtime files to `~/.dent-brain/granola-sync/`.
6. Reload the launchd agent.

Subsequent re-runs of `install.sh` skip the prompt as long as the stored key
still works.

## Cursor migration (automatic, no action required)

The old cursor's `syncedDocumentIds` contains Granola cache UUIDs (e.g.
`f3e45e0f-24cc-...`). The new API uses `not_...` IDs. On the first run of
v0.37, sync.ts auto-strips any non-`not_` IDs from `syncedDocumentIds` and
preserves `lastSyncedCreatedAt`, so you don't re-walk all history. Slug-based
dedup in the brain means meetings already filed under `granola/<uuid>` source
refs won't get re-written when the same meeting reappears under `granola/not_...`
— they log as `existed` and move on.

You'll see one log line on the first run:

```
[granola-sync] migration: dropped N legacy cache UUIDs from cursor
```

## Verification

```bash
# 1. Confirm the key is in keychain
security find-generic-password -s dent-brain.granola-sync -a "$USER" -w | head -c 4
# expected: grn_

# 2. Tail the next scheduled run
tail -f ~/.dent-brain/granola-sync/sync.log
# expected:
#   [granola-sync] Granola API: authenticated
#   [granola-sync] Granola API: N note(s) listed, M candidate(s) ...
#   followed by KEEP/SKIP per-note decisions

# 3. Or force a manual run
bun ~/.dent-brain/granola-sync/sync.ts --dry-run --verbose
```

## If something looks wrong

```bash
# Rotate the key manually (e.g. you revoked the old one in Granola)
security add-generic-password -U -s dent-brain.granola-sync -a "$USER" -w 'grn_NEW_KEY'

# Hard-reset the cursor and re-walk all history (idempotent — slug dedup protects you)
rm ~/.dent-brain/granola-sync/cursor.json
bun ~/.dent-brain/granola-sync/sync.ts

# Uninstall and start fresh
launchctl bootout "gui/$(id -u)" ~/Library/LaunchAgents/com.dent.granola-sync.plist
security delete-generic-password -s dent-brain.granola-sync -a "$USER"
rm -rf ~/.dent-brain/granola-sync ~/Library/LaunchAgents/com.dent.granola-sync.plist
bash tools/granola-sync/install.sh
```

## What did NOT change

- `~/.claude.json` dent-brain MCP entry — the bearer token used to write to
  the brain is still auto-discovered there. No re-onboarding required.
- The org-related filter rules — same four signals (folder, title keyword,
  body mention, attendee domain) and same `orgKeywords` / `orgFolders` /
  `orgDomains` config defaults.
- Idempotency tags — every meeting + transcript page still carries
  `[Source: granola/<note-id>]` (just the ID format changed from UUID to
  `not_...`).
