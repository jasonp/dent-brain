# v0.39.0 Migration: Recipe-model ingestors

This release reshapes how granola-sync and email-sync decide what reaches the shared brain. **If you have either ingestor currently armed**, you need to re-run setup once. **If you don't, nothing to do** — the new flow is the default for any new install.

## Why this changed

Setting up Steve revealed a real privacy concern: a new teammate had no way to know what the hardcoded `dent` keyword + `dentthefuture.com` domain filters would or wouldn't catch on their actual data. Pre-built filters are exactly the wrong contract for personal meetings and personal emails sitting on a work address.

The new design: plugin ships canonical plumbing (Granola API client, Gmail OAuth, MCP write protocol, launchd template) + a `recipe/` with an example filter and contract doc. Every teammate generates `~/.dent-brain/<id>/user/filter.ts` via `/dent-extensions setup <id>` — a conversation with their local Claude that reads their actual data, proposes rules, writes the filter, previews, and only arms after the teammate approves.

## Who needs to act

You need to re-run setup if **either** of these is true on your machine:

- `~/.dent-brain/granola-sync/` exists AND `launchctl print gui/$(id -u)/com.dent.granola-sync` returns 0 (daemon is loaded)
- `~/.dent-brain/email-sync/` exists AND `launchctl print gui/$(id -u)/com.dent.email-sync` returns 0

Anyone with `dent-extensions list` showing `⚠ no-filter` for an installed extension is in the migrated-but-not-set-up state. Run setup to finish.

## Steps for armed installs

**granola-sync:**

```bash
# 1. Re-pull the plugin so install.sh + recipe/ are current
#    (your installed bundle path is opaque; reinstall through Claude Desktop's
#    Plugin Store, or update from your git clone if you have one)

# 2. Re-run install — copies the new lib + recipe and tears down the old plist
dent-extensions install granola-sync

# 3. Bootstrap user/filter.ts. Two options:

#    (a) Conversational (recommended): in Claude Code on your laptop, say
#        "set up granola-sync". The /dent-extensions skill will interview you
#        about what to include + exclude and write user/filter.ts for you.

#    (b) Quick path (reproduces v0.38 behavior): copy the example as-is.
#        Identical to the old hardcoded defaults.
cp ~/.dent-brain/granola-sync/recipe/filter.example.ts \
   ~/.dent-brain/granola-sync/user/filter.ts

# 4. Preview — sanity check before arming
dent-extensions preview granola-sync

# 5. Arm
dent-extensions arm granola-sync
```

**email-sync:** identical shape, substitute `email-sync` for `granola-sync`. The example filter for email-sync defaults to excludelist posture with `DROP_NOISE=true` and no excludes — slightly different from the v0.38 behavior (v0.38 wrote noise into a "Noise" digest section; v0.39 drops it entirely by default). If you want the old behavior, set `DROP_NOISE = false` in `user/filter.ts`.

## What stays

- Your Granola API key in the macOS keychain — untouched.
- Your Google OAuth tokens at `~/.dent-brain/email-sync/google-tokens.json` — untouched.
- Cursor files (`cursor.json`) — untouched. The daemon resumes from where it left off.
- The dent-brain bearer token in `~/.claude.json` — untouched.
- Layer 2 (`dent-process-inbox` skill / scheduled task) — unchanged. Reads digest pages the same way.

## What goes away

- `tools/granola-sync/filter.ts` no longer exists in the repo (moved to `recipe/filter.example.ts`).
- `SyncConfig.orgKeywords` / `.orgDomains` / `.orgFolders` / `.fileAll` no longer parsed by granola-sync (now lives in your `user/filter.ts`).
- Auto-arm on `install.sh`. You explicitly arm via `dent-extensions arm <id>` after previewing.

## What this means going forward

Plugin updates from this release onward will overwrite `~/.dent-brain/<id>/recipe/` and the canonical runtime files (`sync.ts`, `collect.ts`, etc) but **never** `user/filter.ts`. Your customizations are stable across updates. If a future release bumps `RECIPE_VERSION`, the daemon will WARN on the version mismatch but keep running with your old filter; the `/dent-extensions` skill will walk you through a migration conversation rather than overwriting your code.

## Verification

After completing setup, `dent-extensions status <id>` should show `● active` for both ingestors. Tail the log to confirm the first run worked:

```bash
tail -50 ~/.dent-brain/granola-sync/sync.log
tail -50 ~/.dent-brain/email-sync/sync.log
```

Look for `[granola-sync] user filter: …/user/filter.ts (RECIPE_VERSION=1)` and the per-note KEEP/SKIP lines (or equivalent for email-sync). That confirms the new flow is live.
