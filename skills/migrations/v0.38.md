# v0.38.0 Migration: Upstream sync

This is a large fold-in. Twenty-nine upstream commits (v0.30.1 → v0.33.2.1)
land in one merge. Most changes are additive and migrate themselves on first
connect via `gbrain apply-migrations --yes`. A handful surface operator-
visible behavior changes that are worth knowing about before your next
`gbrain` call.

## Operator behavior changes worth knowing

### Multi-source isolation is now strict (v0.32.8)

Pre-v0.38, source-id separation between `'default'` and other sources
(including `'dent'`) was loose. Cross-source slug collisions could
silently land at the wrong source-id and surface intermittent "page
exists but compiled_truth is wrong" symptoms. Upstream's "multi-source
bug class extermination" (#860) tightened this: every read/write that
should be source-scoped now is, end-to-end.

If you ever wrote pages via raw SQL or via the engine API without
specifying `{sourceId: 'dent'}`, those rows may still live at
`source_id='default'`. The dent ingestors (regfox/mailchimp/granola-sync)
all write at `source_id='dent'`. To find stragglers:

```bash
gbrain doctor          # surfaces 'multi_source_drift' check
gbrain sources status  # lists sources + page counts per source
```

The check reports any slugs that exist at `'default'` but NOT at the
intended source. Recovery: run `gbrain sync --source dent --full` to
re-import from the canonical markdown.

### Doctor surfaces more checks

`gbrain doctor` now runs the following new checks (all best-effort, none
blocking):

- `minions_migration` — flags wedged migrations (`status='partial'` ≥3×
  with no later `complete`). If you've ever interrupted `apply-migrations`,
  you may see this fire with a `--force-retry <version>` command.
- `multi_source_drift` — slugs present at `'default'` but not at their
  intended source (see above).
- `subagent_provider` — warns if `models.tier.subagent` resolves to a
  non-Anthropic provider (the subagent loop is Anthropic-only).
- `sync_freshness` — warns sources unsynced >24h, fails >72h. Override
  via `GBRAIN_SYNC_FRESHNESS_WARN_HOURS` / `_FAIL_HOURS`.
- `search_mode` — surfaces current `search.mode` (informational; never
  warns).
- `eval_drift` — flags retrieval-affecting files changed since HEAD
  (informational).

If `gbrain doctor` post-upgrade reports more warnings than before, it's
because there are more checks now — not because your brain got worse.
Run `gbrain doctor` and read each item.

### Search has a mode setting

`gbrain search modes` lists three modes (`fast`, `balanced`, `conservative`)
and shows the current per-knob bundle. Default is unset → balanced
fallback. To pick explicitly:

```bash
gbrain search modes --set balanced
gbrain search modes --reset            # clears per-key overrides
```

Search-lite (a token-budgeted retrieval path with semantic query cache)
ships in this version. The query cache is keyed on the knobs hash, so
config changes invalidate cleanly.

### Hot memory + facts

`gbrain recall` pulls a morning pulse of recent facts. Facts get
extracted during `gbrain sync` (real-time, no scheduled job needed).
`gbrain forget` deletes specific facts. `gbrain cache` introspects the
fact cache.

These are new commands; you don't have to use them. They're additive.

### CLI command additions

New top-level commands: `models`, `recall`, `forget`, `cache`. Each has
`--help` with detailed usage.

## Required operator action

**One step:** after upgrade, run `gbrain doctor` once and clear any warnings
or failures it surfaces. The new checks (multi_source_drift, sync_freshness,
minions_migration) only fire when something is actually wrong, and each
check's message includes a paste-ready fix command.

```bash
gbrain doctor
```

Everything else is automatic.

## Dent-brain specifics

The dent ingestors and the `markdown_*` write path were unaffected by the
multi-source tightening because they were already source-id-aware. Two
test files needed updates to match the stricter semantics (regfox and
doctor-report-remote); existing production data is unchanged.

The plugin marketplace bundle is rebuilt at v0.38.0 via `bun run build:plugin`,
so first-install teammates get the new commands surfaced in their plugin UI
without any manual sync.
