# v0.48.0.0 — Dedicated embed cron + RegFox identity matching

## What changed

- **New background process: a dedicated `embed --stale` cron.** Embedding used
  to run only as the `embed` phase of the once-daily maintenance cycle. A
  transient failure in that slot left newly-ingested pages un-embedded (in the
  DB but invisible to vector search) until the next night, and a recurring
  hiccup let the backlog grow. `src/dent/embed-cron.ts` now runs `embed --stale`
  on its own interval (default 90 min, `DENT_BRAIN_EMBED_POLL_INTERVAL_SECONDS`;
  `0` disables). The pass is idempotent and resumable, so a failure self-heals
  on the next tick.
- **Maintenance cycle names its failing phase.** `nightly-maintenance` now logs
  each failed phase's name + `class/code: message` instead of a bare
  `failed=N/M` count, so a stall is diagnosable from the logs.
- **RegFox name-collision step auto-merges returning attendees.** Previously the
  ingestor matched by exact email only; a registrant with a new email collided
  with their existing name page and was parked in `_ingest/pending_regfox`. A new
  high-precision matcher (`identity-match.ts`) confidently merges when the email
  is tied to the existing page (shared custom domain, shared handle across
  providers) or to the person (surname-as-domain, full name in the address),
  and records the new email into frontmatter `emails[]` so the next registration
  matches directly. Genuinely ambiguous cases still go to pending.

## Will my brain work worse if I do nothing?

**No — it works better, automatically.** All three changes live in the server
(`serve.ts` / the ingestor) and apply on the next deploy with no operator action.
The embed cron starts on boot; any pages that were un-embedded get picked up on
its first tick (no manual backfill). The RegFox change only affects new
registrations going forward.

## Operator notes (optional)

- **Tune or disable the embed cron** with `DENT_BRAIN_EMBED_POLL_INTERVAL_SECONDS`
  (seconds; default `5400`; `0` disables). It is safe to run often — `embed
  --stale` only touches chunks whose embedding is NULL.
- **`_ingest/pending_regfox` should stay small.** Only registrations with no
  confident identity signal (an unrelated personal email, a known same-name
  split) land there now. Review it occasionally; resolving a row by adding the
  email to the right person's `emails[]` makes future registrations from that
  address match directly.
- **Two different people who share a name** are kept apart: once a `<slug>-N`
  variant exists, name-only signals are suppressed and the registration goes to
  pending for a human call rather than auto-merging.
